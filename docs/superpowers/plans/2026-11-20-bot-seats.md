# Bot seats Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Joiners take a bot's seat (lobby and mid-match); when they leave, that bot comes back.

**Architecture:** Lobby seats only the first `MAX_PLAYERS − humans` of `lobbyBots`. In a match, a human's record holds
the bot it displaced as `bumped`; `dropConn` puts it back, stashing the human's stats in `M.away[name]`.

**Tech Stack:** single-file `blast-grid.html`, Node `node:test` + `tests/harness.js` vm harness.

**Spec:** `docs/superpowers/specs/2026-11-20-bot-seats-design.md`

## Global Constraints
- No snapshot / lobby message format change; `ID_PREFIX` unchanged.
- `MAX_PLAYERS` (4) humans is still "Room is full".
- Bot that comes back keeps its `name`, `bot` level and stats; joiner never gets a bot's wins.

## Review Focus
- Rematch (R) after hot joins must never produce more than 4 players → test in Task 1.
- Leaver rejoining under the same name after a bot took their seat gets their stats and seat back → Task 2.
- Bot taking over must not fire a bomb on its first think (keeps input counters) → covered by `botThink` reusing `inputs[slot]` counters; Task 2 asserts no new bomb right after takeover.
- A guest that left without bumping a bot still leaves an empty seat → Task 2.
- Host alone with bots after all guests leave keeps playing (no "back to lobby") → existing behaviour, untouched.
